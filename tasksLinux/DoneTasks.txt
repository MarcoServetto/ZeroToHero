Report:
Read Frontend's real tokenizer/parser (TokenKind.java, Token.java,
Parser.java) and cross-checked against 88 real .fear files in
StandardLibrary rather than guessing at the grammar. Finding: types
(identifiers plus all 4 literal forms - literals really are types per
Token.typeName) and method names (the glued .name token) are 100%
regex-safe; parameter names are not - only declaration sites are
heuristically detectable with a regex-level grammar, uses need a real
parser/binder (an LSP backed by Frontend itself). The three comment styles
(/// //> //- //) split cleanly via a documented string-prefix priority.
Recommendation: ship a cheap TextMate grammar now for the regex-safe
categories, treat LSP-backed semantic highlighting as a separate future
investment for parameter names. Built a POC fearless.tmLanguage.json and
tested it with the real vscode-textmate/vscode-oniguruma engine against all
88 StandardLibrary .fear files - 0 unclassified characters; found and fixed
two real bugs along the way (operator run swallowing // comments;
single-line block-comment pattern). This is a design discussion, not a
finished feature: proposal.md, the grammar, and a README are left at
/data/fearlessBranch3/overnightLogs/fearless-highlighting/ (machine-local,
