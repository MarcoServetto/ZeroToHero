Facts learned (do not rediscover them):
- The GNOME desktop (DING) does not run a bare executable on double click ("Failed to find default application for content type application/x-executable") and does not accept drops on it; GNOME Files runs it on double click but treats a drop onto it as a drop into the folder shown (it COPIES the dropped folder there: never do that to the deployed image). Hence the .desktop launcher.
- Xfce runs a bare executable on desk double click and passes dropped folders to it.
- Xfce's first start of the manager from a freshly mounted share takes many seconds: wait for the screen, never for a fixed short time.
- Robot VK_WINDOWS (Super) did not reach a guest; no test needs it.
- An aim read inside until(...) is asked again at every iteration in agent mode: read aims once before the loop.
- A field initialised with a lambda creating an inner class in the public PilotTest trips javac's this-escape warning (-Werror): create such objects lazily.
- DeployManagedFearless.java empties StandardLibrary/fearlessManagedArtefact, which currently holds the guest desk folder: move the desk folder somewhere no build deletes (and update the guests' ~/Desktop link) or re-create it in lay().
- Over ssh, pkill -f / pgrep -f match the ssh shell itself when the pattern is in the command line; date +%s%3N is not milliseconds here, use $(( $(date +%s%N)/1000000 )).
- Clicks through xdotool inside a guest did not reach the Java window; drive guests only from the host through the viewer.
- FearlessGuiTest is not a desk test: it starts a Fearless program by ProcessBuilder to test Pilot itself. It stays a host test and must not run on guest desks.
- Tiling guests without desktop icons (arch-sway, void-i3, omarchy-hyprland) cannot do "double click the launcher icon": what a person does there instead is a question for Marco; record which tests apply and stop there.
