Task:
Make the agentTools tests of FearlessLang/Controllers pass on the current manager, first on ubuntu_gnome, then on the 12 VMs.
What the manager does is in ZeroToHero/tasks/ControllersDesign.
The tests are in Controllers/test/agentTools; they run with Coordinator/Build/src/scripts/TestAgentTools.java, one test at a time.
How a person drives a GUI is in /data/gym/gui_gym.txt; how to drive a VM is in /data/gym/gui_vms_gym.txt.
The steps, in this order:
1. Run the align-branches skill in the workspace of the task.
2. Finish converting the tests to the current design, on ubuntu_gnome.
   The screen of ubuntu_gnome is 1920x1080 at scale 1.
   The recordings of ubuntu_gnome were made on a 3840x2160 screen.
   Inside the manager window the positions are the same, because Swing does not scale.
   The positions that depend on the screen must be recorded again: the screen centre, the centred dialogs, the tray icon, the file chooser, the metadata editor buttons, the terminal and the apps launcher.
   The description of FearlessLang/Controllers PR 91 lists the tests that failed and why.
   A pressed button stays disabled for half a second and the keyboard focus moves to the next button: a compared screen area leaves both out.
   The tray icon now opens its menu on a click with any button, and the simulated desktop fills the window while no project is selected: test both.
   Make every wait long enough that a slow start does not fail a test.
3. Run every test on ubuntu_gnome.
   When a test can not pass reasonably on this machine, find the cause and open a PR that fixes it:
   - the test is wrong: fix the test;
   - the manager does not follow the design: fix the manager, with a test;
   - Pilot can not do what a person does: fix Controllers/src/agentTools, keeping it free of anything that only this machine has;
   - the design does not allow the test to pass, or says nothing about the case: open a PR to ZeroToHero changing ControllersDesign, and write no code for that case; the user reviews the design first.
   Then run every test on ubuntu_gnome again.
   Repeat step 3 until every test passes, or until the only failing tests wait for a design PR.
4. When every test passes on ubuntu_gnome, run every test on each of the 12 VMs.
   Each VM is 1920x1080 under the viewer: record the positions of each test for each VM.
   Fix what fails as in step 3, and run the whole package on that VM again before moving to the next VM.
   Only one VM runs at a time; a VM is shut down (virsh shutdown) after its round.
Each step runs in its own sub agent (opus, high effort); the next step starts when the previous one has finished.
Every PR goes to the parent repository from a branch of the marcoautomation2 fork; its body is the report of what it changes and why.
Each sub agent writes a log of what it did and found, per test and desk, in /data/overnight_logs/agent_tools, named <test>_<desk>.txt in lower case; the logs stay on the machine.
The results reach the user through the PRs and the overnight report PR; nothing else needs reporting.
At the end, and between test runs, the desk of ubuntu_gnome is bare: no manager, no terminal, no file manager process.
