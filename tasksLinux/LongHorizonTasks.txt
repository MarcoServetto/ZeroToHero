This is a single long task. The structure of the tasks ask you (linux3) to be the outer agent that summon the inner agent when needed.
You can assume that linux1,2,coordinator will be idle; thus there should be only two active agents and only one agent running in any moment of time, you/linux3/outer or inner.


Task "CommonsBugs":
You (linux3) are the outer agent; the sub agents you start are the inner agents.
Run at most one inner agent at a time. Every agent should be Opus 5.5 high.
Inner agents write no logs; this task overrides the global rule on sub agent logs.
Every inner agent starts in a fresh environment, with no trace of the activity of earlier inner agents.

Setup:
- If a PR of this task from an earlier night is still open on
  FearlessLang/Commons, stop and report it.
- Otherwise, in your working copy of Commons, create the branch
  CommonsBugs from upstream main, push an empty commit, and open the PR.
- Run TestAllFrontendCoordinator.java and note the failing tests.

Rounds:
Before each step, check the usage limits. Do not worry about getting near the weekly limit, all good.
If the current 5 hours session is over 80%, sleep until 5 minutes after the session resets,
as the overnight rules describe.
Do not start a new round after 8am.
1. Copy Commons/src of the branch into a new empty folder <folder> in your
   scratchpad, without any git data, together with
   ZeroToHero/tasks/ruledOut/CommonsBugs (as <folder>/ruledOut).
   Start an inner agent:
   """Read only files inside <folder>. Read all the code in <folder>/src.
   Identify one kind of bug: a mistake that is likely to happen in several places,
   not one place. Think about the logic of the code.
   Then write a test showing that the bug is real. Do not fix the bug.
   The behaviour marked Good in <folder>/ruledOut is intended.
   Reply with the kind of bug and one concrete input with the wrong result it
   produces. Do not run your test showing that the bug is real, focus on
   reasoning only. Running the test is not your responsibility."""
2. Delete the folder. Run the test yourself and decide if the bug is real.
   Record it in ZeroToHero/tasks/ideas/CommonsBugs: one line per kind of bug,
   marked reported or refused, with how many times it was proposed; a kind already in the file, even with different words, increases its count.
   If you refuse it, go back to 1. After 5 refusals in a row, stop.
3. Open a new PR for this specific bug on Commons.
   Start an inner agent:
   """On the branch CommonsBugs of Commons, read all the code in
   Commons/src and consider this bug report <provide bug report PR link>.
   Run TestAllFrontendCoordinator.java: only these tests and the new ones may
   fail: <list>. Is this bug an isolated thing or can it be generalised into a category of wrong behaviour affecting other places? Fix either the isolated bug or the whole category. Check that the bug is now fixed by seeing the tests pass. If the bug was not an isolated case, add more tests to cover other representative cases. Do not add redundant tests. Amend the PR."""
4. Read the new state of the PR. Decide if any twist is needed.

Stop when one of the following is true:
- there are at least 10 different PRs for 10 different bugs
- the refusal limit is reached (this may be because the same bug is encountered over and over again)
- some of the encountered bugs are preventing the agents from finding new bugs because the found bugs interact badly with finding new ones until those PRs are integrated
- the time limit is reached.

Otherwise, restart from point 1, while providing the agents with the code of
Commons as it is now, not as it would be with those PRs accepted.

Make sure at the end there is a PR for Commons, and one for ZeroToHero with the ideas file and the done tasks.

Report: the content of ZeroToHero/tasks/ideas/CommonsBugs, and the
clickable links to all the opened PRs.
