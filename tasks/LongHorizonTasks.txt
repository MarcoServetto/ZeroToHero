in-session task: "Files read/write"

The fearless manager supports data projects, and supports some fearless projects being able to read/write those files.
But the fearless standard library does not have any connection here.

Design two new capability:
CapDataRead
CapDataReadWrite
Those can be obtained by the system as for others.
The api is as follows:
.paths(name:Str,path:List[Str]):Action[List[Str]]//on both
.read(name:Str,path:List[Str]):Action[InputCursorNode] //on both
The 'File' must be the same thing that open with now gives.
'name' is the alias of the data project that the manager lets the user see.
path is a list of strings denoting the path from the root of the data project to a file.
Invalid if it is a directory.
The path must be able to transparently enter in zips, while the zip file itself is conceptually invisible.
.paths give all the files/folders at the inner path 'path'.
Info if the inner path does not denote a folder (or a folder in a zip)

.writeStr(name:Str,path:List[Str],content:Str):Action[Void] //only in CapDataReadWrite
.delete(name:Str,path:List[Str]):Action[Void] //only in CapDataReadWrite
Similar, but only on the write capability.
In addition to .writeStr we will need many variants, supporting writing images and strings/ustr with various encodings.

Crucially, the manager must cooperate for this to happen.
When the main start the manager must inject the map from logical aliases to validated Java paths.
The manager must prevent any permission change while the program run.
If the files somehow change on disk in a way that prevents the read/write, we get a non deterministic exception. That is, there is not continuos checking that the folders are still ok, but if when reading we find issues about the specific reading/writing we are doing, we do get an error.

Take your time this is a large task.

After completed, review you work 5 times.

Then open the relevant PRs.
