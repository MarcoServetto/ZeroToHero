We want to be able to use fearless like this:
Foo:Main,OpenWith[AutoloadedIcon,"extension"]{}
Foo:Main,Shortcut[AutoloadedIcon,"extension"]{}
Foo:Main,OpenWith[AutoloadedIcon]{}
Foo:Main,Shortcut[AutoloadedIcon]{}
(where AutoloadedIcon is any type created as a response of an image file recognised as an autoloaded asset. Note that it can be in any package and base will soon offer a large list of useful defaults)
Informally, this means that the main wants to be associated so that double click on files with that extension will open that main and that those files should have that icon.
Counter intuitively, on a mechanical perspective, Shortcut is the exact same, but in the mind of the programmer the 'shortcut file' has no information, thus resulting in a simple way to open that main.

Actually, the manage will associate all of those to itself and pass the file url as part of the normal manager commands; then it will check how is that extension associated and trigger the right main.

If no extension, the manager auto assign one using the algorithm explain below. In rare cases compilation order may cause different extensions to be assigned if the code does not specify one. This is accepted.
This is sane in a world where extensions are either actually hidden or ignored by users, that just use the images to understand using their apps.
(Ignore for now:On MacOs (eventually) we may have to ignore the user provided extensions that are not in the default list, and ignore the icon if not in the default list.)

we need to add to base the following
OpenWith[Icon,Extension]:{}
Shortcut[Icon,Extension]:{}
OpenWith[Icon]:{}
Shortcut[Icon]:{}

Note: Shortcut intentionally does not extend OpenWith
Note: a main can legally implement both OpenWith[Icon1,"a"] and OpenWith[Icon2,"b"] at once to get more extensions for the same main.
The Icon can vary (as shown Icon1,Icon2) or stay the same.
Multiple Shortcut are also possible and would just produce multiple top level files calling the same main, possibly with different icons. In the future the main may ask system for details of the shortcut filename etc and select behaviour over it.

Type system checks they are only implemented on something that extends (even indirectly) Main; see how it works for Sealed etc with how to add it to the TypeSystem. Of course a part of those checks go in the opposite direction wrt Sealed:"the implementer must also carry Main among its own supertypes.", so some new logic is needed. The type system should (of course) blame the interface implementing OpenWith/Shortcut for not also implementing main. Use the other errors to understand what would be the best wording.

Type system will check that the Extension is a text that respects the intended format for extensions (see what is allowed to be in a project).
That is, we do expect the user to write exactly a string literal in the second generic argument; this is possible in fearless since those are syntactically just types. It is acceptable in both forms: `txt` or "txt", and there should be no difference in how the compilation handles them.

Controller will check that the Icon is indeed an autoloaded Png, square and with an appropriate size (help me decide the appropriate range). If not it will mimic as close as possible a type error, but since this is about looking into an image file, the task should not be performed by the frontend.

- add an association to that Icon with the fearless manager.
- make sure to fill the "mains.info" file in .fearless_out with the needed information.
(Today the information is duplicated and messed up, we need a clean up to do this work:

Where each Main is associated to the list of all extensions; first the list of Shortcuts then the list of OpenWith. Those lists can be empty no problem.
The manager running program should then construct the opposite map (extension->list of mains claiming it) but not save it on disk; keep it in memory and reconstruct it from the managed .fearless_outs on manager restart.)

If there is more then one conflict, one conflict only is displayed. Select the first one in alphabetical order.

-Compiling with Shortcut is actually exactly the same; but in addition a file
 "foo.extension" will be created (empty) in the top level of the fearless project containing this main. The user can then use that file to double click to open the main, or drag-drop this file anywhere they like to... still open it from there with a double click.
 Note: foo is the name of the main implementing Shortcut twisted to be valid in the projects exactly the inverse way auto imported assets are twisted to be valid type names, and extension is the user provided second parameter to Shortcut, or the autoselected one by the manager.
 The inversion is well defined: at a first glance one may thing that both foo_bar.png and fooBar.png both go in FooBar; but actually fooBar would be an invalid name in the project, since all file names under a project must have no uppercase letters. There is only one valid way to invert the transformation.

 The manager gui will then show the icons of the 'shortcutted mains' in the view for that project and double clicking on them will start them. 

FileAssociations.reconcile is keen to do stuff as a single chunk, so for each compilation of a project that does change association, we need to recompute the new desired full set of fearless manager associations.
Extensions already associated (by another fearless project) will need to get the conflict icon.

If FileAssociations.reconcile do fail, the controller will fail the whole compilation with a reasonable error message, inspired by other error messages. We may have to refactor FileAssociations.reconcile to expose enough details to give a good error.

Autoselecting: the manager will select for Shortcut an extension of the form fappNNN (example, fapp003, fapp042, fapp995)
where NNN are three digits 0-9. The manager will mangle the project name and main name and hash them to get a 0-999 number. That number, if free (non fearless assigned extension by this very manager), is selected; else select the next number; repeat until a free number is found (overflowing to zero if needed).
Yes, if all the 1000 numbers are selected, some error will be given to the user. Wording it will be difficult.

Autoselecting: the manager will select for OpenWith exactly as for Shortcut, but the extensions will be of form ffileNNN instead.
