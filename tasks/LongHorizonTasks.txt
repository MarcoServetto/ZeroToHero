I read the whole type checker (typeSystem/*, core/*, the inject/inference layer feeding it) and then attacked it with probe programs compiled against the built Frontend. Every attempt to break immutability failed correctly: capturing mut into imm methods and escaping via promotion, read -> imm result strengthening with fresh state, iso params captured plus used, read/imm X with iso/hygienic bounds, iso Box[mut A] element extraction, leaking a read alias out of a readH/mutH argument through a closure (the H results stay hygienic because mutH is not a subtype of read), generic invariance vs. X/rc X redundancy. The capability calculus is implemented faithfully; I could not produce a mutation of an immutable object.

The bug I did find: an iso object literal cannot refer to itself

An explicitly iso literal with a self name rejects every use of self, with a wrong diagnosis:

parameter "self" has type "mut Counter".
parameter "self" can observe mutation; thus it cannot be captured in the "iso" object literal instance of "iso Counter"

Mechanism: TypeSystem.litOk (Frontend/FearlessFrontend/src/typeSystem/TypeSystem.java:179) adds this to gamma as mut Counter (rc.isoToMut()) and then runs ViewPointAdaptation.of over the whole gamma, self included. ViewPointAdaptation.discard (ViewPointAdaptation.java:40) treats self like any external captured variable: literal is iso and mut Counter is not iso/imm, so DropMutInImm. The drop rule is right for captured variables (an iso literal must not alias outside mutable state) but self is the object itself, not something captured. For mut/read/imm literals the same code path happens to compute the right this type (mut/read/imm per method), which is why it went unnoticed.

There is no workaround: the promotion route (mut Counter{'self ...} returned as iso Counter) is deliberately closed for named literals (checkLiteral requires thisName == "_"), so today no iso literal can name itself. mut/read/imm methods all fail the same way (probed all three, plus self.inc.inc chains).

Two controls that pass today and should keep passing (worth adding next to it so the fix does not over-reach): iso Box{ read .get: A -> a } with a: iso A (captured iso becomes imm, fine), and the unnamed mut Counter{...} returned as iso Counter (promotion).
