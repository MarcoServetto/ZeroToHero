Good:
  A builder call builds detached, then installs in one EDT block.
  All handlers of one event (a click, a mouse event, a hover transition, a model tick, a key) and the whole model task run as one task: layout, render and rehover happen when the task ends.
  A new .mouse, .onKey, .modelFps, Button.action or ModelFps.action replaces the previous one.
  A widget or builder no longer in the window refuses changes, except inside .changeDetached{...}.
Bad:
  .mouse, .onKey and .modelFps add to the existing handlers.
Why: replacing is the only way to drop a handler.

Good:
  The window raises no geometry error: it moves so that min(screen/3, window size) stays visible on each axis, also after the user drags it.
Bad:
  A geometry check against the window position or size, which the user drags and resizes.

Good:
  Sizes given by the program are content sizes.
  Style and drawing values have one fixed limit, independent of the screen.
  A Frame rule is enforced at render time or at the offending call, the same before and after start.
  Every layout asks the size at a given width of every child, at every level.
  Hover is recomputed from the pointer after every geometry change.
  Layout runs also while a mouse button is held.
  .onKey delivers .released to the key map whose .pressed fired.
  A key name is checked against the Java key names; held keys pair per physical key (code and location).
  A widget offers a setting only when it honours it.
  A still GUI allocates nothing per frame.
  Graphics.position moves the one pen and returns this.
  Rect.contains is half open, as java.awt.Rectangle.
  Hue is in 0 =~~ 1.
