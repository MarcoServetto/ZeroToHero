Good:
  EditMetadata replaces projects.info with the text of its file, whatever projects.info holds
  when the manager applies the message. A text made from an older projects.info is applied
  as it is: restoring a saved projects.info is one of the uses of EditMetadata.
  Register of "hello", then EditMetadata with a text saved before that Register   forgets "hello"
Bad:
  EditMetadata refuses or merges a text because projects.info changed after the text was made.
  (only the window knows what the user saw: the window checks that projects.info did not
  change while it was edited, and the window builds a text adding to projects.info from the
  projects.info of the moment the user accepts. A message the manager applies between that
  check and the EditMetadata message is overwritten.)
Good:
  The manager receives absolute paths only: a message holding a relative path is refused.
  The manager program started with a FearlessCommand makes a relative path absolute, from
  the working folder it inherits from the program that started it.
  FearlessCommandRegister Str:hello   started from C:\work   is the message   Register Str:C:\work\hello
Good:
  A message is never lost: a message file the ending manager does not drain stays in the
  messages folder, and the next manager applies it when it starts.
  Quit while the old manager ends, then a new start   the new manager applies that Quit and ends
