Good:
  Message takes a column as a char index and expects no tab before a reported position.
Why: sources pass Fs.allowed, and tokenizing stops at the first character outside it.

Good:
  A span whose last token ends with a newline ends at column 1 of the next line; the file span ends one past the last character.
Why: only white space and an unclosed block comment end with a newline, and their errors read the same either way.

Good:
  MetaParser.peekLast does not check that the last token is not consumed from the front.
Why: the back end is consumed only for the closer of a group whose opener was just consumed, or before the front consumes anything.

Good:
  MetaParser.spanAround(low, high) takes the span of its two end tokens.
Why: the Fearless parser skips only _SOF and _EOF, consumed before any span is taken; postTokenize removes white space.

Good:
  Message draws a caret only inside the text of a line.
Why: Frontend reports only spans starting on a real token.

Good:
  MetaTokenizer.whiteList counts positions from 1:1.
Why: Parse, the only tokenizer, starts at 1:1.

Good:
  LinuxAssociations.mimePackage writes the identity in <comment> without XML escaping.
Why: identities, extensions and icon names are generated and hold no XML special character.
