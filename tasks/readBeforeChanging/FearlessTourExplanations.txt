Good:
  Spaces are irrelevant.
  We will see this later in the guide.
Bad:
  Spaces are irrelevant (text in quotes, met later, is the exception).
  We will see this later in the guide (Chapter 4, offensive programming).
  This code is not ideal: ... ; it also underflows, but we ignore this here.
Why: caveats, pointers and parentheticals pull the reader away from the point of the paragraph.

Good:
  `.turn -> East;` is a **method declaration**
  those parentheses are needed.
Bad:
  `.turn -> East;` is a **method implementation** (a method declaration with a body)
  the parentheses around `2 * 3` are needed to obtain `7` from `1 + 2 * 3`.
Why: a sentence clear to the reader needs no more precise version.

Good:
  This process is called evaluation.
Bad:
  This process is called evaluation; each step is called a reduction.
Why: a sentence answers a question the reader has at that point; a textbook name is no such question.

Good:
  there are exactly two ways
Bad:
  so far there are two ways
Why: "so far", "usually", "mostly" make the reader look for cases the guide never shows.

Good:
  a 5 symbol annotation
  balanced parentheses
  the generic type `[Val]` ... takes two arguments of type `Val`
Bad:
  a 5 character annotation
  balanced brackets
  the generic type parameter `Val` ... takes two parameters of type `Val`
Why: terms follow how the reader understands them, not the technical vocabulary.

Good:
  I still vividly remember the moment it struck me ... Mind blowing!
  if I wanted to concatenate them, I could do
Bad:
  This ability is a cornerstone of the pure object-oriented style.
  if we wanted to concatenate them, we could do
Why: the enthusiastic first person voice keeps the reader going.

Good:
  `Foo#(bar)` may not compile: you may have to write `Foo#[Bar](bar)`.
Bad:
  `Foo#(bar)` does not compile.
Why: the inference is not fixed; a "may" sentence stays true whatever the inference accepts.

Good:
  Stack[E]   Order[T]   Action[R]
Bad:
  Stack[T]
Why: E is an element, T the implementing type, R a result, as in the standard library.

Good:
  *|/
Bad:
  */
Why: "*/" ends the Java comment; the html generation turns "*|/" into "*/".
