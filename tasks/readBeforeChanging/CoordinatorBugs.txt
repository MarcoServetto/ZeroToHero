Good:
  A type replaced by a hand-written rt file keeps the source file and the lines of its Fearless declaration:
  _base/Lists$1c$0.class   is compiled from datatypes/collections/lists/list.fear
  imm _RunRecursion#(_,_) error line: 24 in file run_recursion.fear   is a frame of a stack trace
Bad:
  _base/Lists$1c$0.class   is compiled from Lists$1c$0.java
  a stack trace drops the frames of _RunRecursion#(_,_), since they come from a .java file
Why: a type replaced by an rt file is a Fearless type with a special implementation, and its frames are frames of the Fearless program.

Good:
  The compilation cache (.fearless_out) checks the files it records and their modification times; nothing else.
  A user who changes files in a way that escapes those checks gets whatever the cache holds, and that is not a bug.
  For example: a source file put back with an older modification time, a .fearless_out edited by hand or copied from another project, a project opened by another installation whose base.json is older.
  Such a user runs Delete cache.
Bad:
  A bug report or a failing test about a change of the files that the cache checks do not see.
  .built records a hash of every input, so that the cache notices every change.
Why: the cache is not signed. A check for each way to change files behind the back of the cache is a list with no end, and each check costs time at every compilation.
